# Changelog

## 2026-09-26 — God-панель: поиск диалогов больше не падает молчаливой 500

### Что сделано
- Оба server action вкладки «Удаление» (`secretSearchConversationsAction`, `secretHardDeleteConversationsAction`) обёрнуты в try/catch: любая ошибка БД (нет соединения, не применена миграция и т.п.) больше не превращается в непрозрачную HTTP 500 «Failed to load resource», а возвращается как читаемое сообщение и логируется на сервере (`console.error('[v0] …')`).
- Поиск при ошибке возвращает `{ rows: [], total: 0, error }`; для `42703` (нет столбца) подсказывает выполнить `pnpm db:migrate`.
- UI (`secret-dialogs-tab.tsx`) показывает реальный текст ошибки через toast — видно, ЧТО именно не так, вместо пустого списка без объяснений.

### Причина
- Раньше при любой ошибке запроса action бросал исключение → Next отдавал 500, клиент показывал generic-тост, а настоящая причина (например, отсутствие `DATABASE_URL`/столбца в конкретной БД) была не видна. Сам SQL-запрос корректен: все столбцы (`contact_username`, `god_synthetic`, `is_simulated`, `curator_id`, `channel_type`, …) существуют в миграциях ≤171 и используются рабочим кодом.

### Где
- `app/actions/admin-secret/dialogs.ts` — try/catch + структурированный `error` в результате поиска, чистое сообщение при удалении.
- `components/admin/secret-dialogs-tab.tsx` — показ `res.error` через `toast.error`.

### Как проверено
- `npx tsc --noEmit` — без ошибок.
- В текущем окружении v0-preview `DATABASE_URL` не задан (подтверждено: инвентарь env содержит только `NEXT_PUBLIC_DEV_SUPABASE_REDIRECT_URL` и AI Gateway) — поэтому любой DB-запрос тут отвечает 500; на проде, где БД подключена, запрос отрабатывает. Теперь при отсутствии БД пользователь видит понятное сообщение, а не пустой экран.

## 2026-09-26 — God-панель: безвозвратное удаление диалогов

### Что сделано
- Добавлена новая вкладка **«Удаление»** в god-панель с максимально гибким поиском по всем диалогам системы и возможностью полностью, безвозвратно удалить любой диалог (или несколько сразу).
- Поиск работает по любым критериям: текст (имя/логин/телефон/email контакта, заголовок диалога, содержимое сообщений, внешний id), канал, назначенный менеджер, статус диалога, наличие непрочитанных, диапазон дат последней активности.
- Удаление каскадное и необратимое: чистит сам диалог и все связанные записи (сообщения, вложения/медиа, черновики, прочтения, назначения, теги и т.п.) в одной транзакции — по образцу существующих purge-скриптов.
- Перед удалением — обязательное подтверждение с явным предупреждением о необратимости; действие пишется в audit-trail (`audit()`).

### Где
- `app/actions/admin-secret/dialogs.ts` — новые server actions: поиск (`secretSearchDialogsAction`) и безвозвратное удаление (`secretPurgeDialogsAction`).
- `app/actions/admin-secret.ts` — реэкспорт новых экшенов из barrel-файла.
- `components/admin/secret-dialogs-tab.tsx` — UI вкладки: панель фильтров, список результатов с мультивыбором, диалог подтверждения удаления.
- `components/admin/secret-dashboard.tsx` — регистрация вкладки «Удаление» (иконка `Trash2`, секция `dialogs`, ленивый импорт и рендер).

### Как проверено
- `npx tsc --noEmit` — проходит без ошибок (в т.ч. по новым файлам `dialogs.ts` и `secret-dialogs-tab.tsx`).
- Вкладка доступна только внутри god-панели за существующим fail-closed гейтом (`requireAdmin`), путь `/wijegniwjgwjog`.
